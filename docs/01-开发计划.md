# 01 · 开发计划

> 项目：现代设计史 · 在线复习刷题站（暂定代号 `dsquiz`）
> 版本：v1.0 ｜ 编写日期：2026-09-13
> 硬约束：**2026-09-15《现代设计史》考试**，可用开发周期约 2 天

---

## 1. 项目定位

把已有的 4 份作业题库（共 **78 题**：单选 33、填空 23、判断 18、多选 4）与 30 页课件知识点，做成一个**部署在 GitHub Pages 上、移动端优先、支持多人同时在线复习**的刷题站。

一句话成功标准：

> 9 月 15 日进考场前，用这个站点完成至少 3 轮全量刷题 + 1 轮错题重做，且能和同学开一个房间同步刷题。

### 1.1 为什么不是「先做完整产品」

只有 2 天。因此本计划的第一原则是 **MVP 优先、可用优先于完备**：

- **D0 当晚**就要有一个能真正开始刷题的上线版本（哪怕多人都没有）。
- 之后每加一个功能都是一次可独立上线的增量，随时可以停在任一版本进考场。
- 任何功能的取舍标准只有一条：**能不能提高 9/15 的分数**。

## 2. 已知条件与约束

| 类别 | 内容 | 影响 |
|---|---|---|
| 时间 | 考试 2026-09-15，今天 9/13 | 排期以「半天」为最小粒度 |
| 托管 | GitHub Pages，纯静态，**无服务端** | 多人同步必须走 P2P 或第三方免费实时服务 |
| 数据 | 4 份 Markdown 题库 + 1 份 PPTX | 已结构化为 JSON，见 `data/`（**已完成**） |
| 用户 | 本人 + 同学，≤10 人 | 不需要账号体系，昵称 + 房间码即可 |
| 设备 | 手机为主、电脑为辅 | 移动端优先设计，手势可操作 |
| 网络 | 考场/宿舍可能弱网 | 必须支持 PWA 离线刷题 |

## 3. 范围定义（MoSCoW）

### P0 — 必须完成（目标：D0 当晚可刷题）

| # | 功能 | 说明 |
|---|---|---|
| P0-1 | 题库全量结构化 | ✅ 已完成，78 题 + 判分字段 |
| P0-2 | 练习模式 | 顺序 / 随机 / 按题型 / 按章节 四种入口 |
| P0-3 | **答题即时反馈** | 选完立刻判分：对错高亮 + 正确答案 + 解析（核心体验） |
| P0-4 | 本地持久化 | 进度、错题、连续打卡存 localStorage |
| P0-5 | 移动端适配 | 单手可答，按钮 ≥ 44px，横竖屏不崩 |
| P0-6 | GitHub Pages 上线 | 有可分享的公开 URL |

### P1 — 重要（目标：D1 完成）

| # | 功能 | 说明 |
|---|---|---|
| P1-1 | 错题本 | 自动收集，支持「一键只刷错题」 |
| P1-2 | 间隔重复 | 简化 Leitner/SM-2，到期题优先推送 |
| P1-3 | 速记卡 | 31 张知识点卡片，抽认式记忆 |
| P1-4 | 大题自测 | 14 道简答/论述，踩分点关键词命中 + 自评 |
| P1-5 | PWA 离线 | Service Worker 缓存，考前无网可刷 |
| P1-6 | 多人房间 | 房间码建房/加入、成员进度实时可见 |

### P2 — 加分（有余力再做）

- 抢答 PK 模式（同题竞速、计分排行）
- 学习数据统计（正确率趋势、章节薄弱点雷达）
- 跨设备云同步（Supabase 免费层 + RLS）
- 全站排行榜 / 成就徽章

### P3 — 本期明确不做

用户注册登录、后台 CMS、图片与音视频题、语音朗读、错题自动归因 AI 分析。

> 不做的理由：这些功能对 9/15 的分数没有可测量的正向贡献，但会吃掉 50% 以上工期。

## 6. 范围裁剪预案

时间不够时，**从下往上砍**，砍掉的顺序即优先级倒序：

| 优先级 | 裁剪动作 | 影响 | 触发条件 |
|---|---|---|---|
| 1 | 砍抢答 PK、统计图表 | 无（P2 本就加分） | 落后 > 4h |
| 2 | 砍 MQTT 降级实现，只留 PeerJS | 个别网络连不上时只能单机 | 落后 > 6h |
| 3 | 砍速记卡模块 | 用大题自测替代 | 落后 > 8h |
| 4 | 砍多人房间，改「本地多标签广播」演示 | 无法真正多人，但可答辩 | 落后 > 12h |
| 5 | 只保留单机刷题 + 错题本 | 降级为纯刷题工具 | 落后 > 16h |

> **绝不砍的三件事**：题库正确性、即时反馈、移动端可用。这三件是考试提分的直接来源。

## 7. 风险登记册

| ID | 风险 | 概率 | 影响 | 应对策略 |
|---|---|---|---|---|
| R1 | 题库存在错误答案 | 中 | 高（误导复习） | 数据版本化 `schemaVersion`；页面提供「纠错」入口收集反馈；上线前人工抽检 20% |
| R2 | GitHub Pages 更新延迟（CDN 缓存） | 中 | 中 | 构建产物带 build hash；必要时加 `?v=` 查询串强制刷新 |
| R3 | WebRTC 打洞失败，房间连不通 | 高 | 中 | 三级降级：PeerJS → MQTT 公共 broker → 单机模式；房间页显式提示当前通道 |
| R4 | 时间不足，功能做不完 | 高 | 中 | 见第 6 节裁剪预案；M1 当天必须上线 |
| R5 | 弱网/考场无网 | 中 | 高 | PWA 预缓存全量 JSON（仅 ~150KB），离线可用 |
| R6 | 移动端答题误触（多选/填空） | 中 | 中 | 选项卡片 ≥44px；填空题支持键盘类型切换；答案提交前可修改 |
| R7 | 多人房间被陌生人混入 | 低 | 低 | 房间码用 6 位随机；只广播昵称与进度，不广播答案明文 |
| R8 | 第三方免费实时服务限流 | 中 | 中 | 信令/消息频率节流（≥300ms）；重连退避 |

## 8. 验收标准（Definition of Done）

单个功能算「完成」需同时满足：

1. 功能在 **375px 宽**（iPhone SE）与 **1440px 宽**下均可用且不溢出；
2. 核心逻辑（判分、调度）有单元测试且通过；
3. 首屏在 4G 下首字节 < 1.5s，数据加载后无白屏闪烁；
4. 断网刷新仍能进入已缓存页面；
5. 合并到 `main` 后由 Actions 自动部署成功。

### 全局验收清单（D2 考前执行）

- [ ] 78 道题的正确答案与速查表逐题比对一致
- [ ] 每个题型的即时反馈都能正确显示对错与正确答案
- [ ] 填空题容错生效（空格、标点、全半角、数字写法差异不判错）
- [ ] 错题本在清空浏览器缓存前持久保存
- [ ] 手机浏览器（Safari / Chrome / 微信内置）各实测一轮
- [ ] 两台设备成功进入同一房间并看到彼此进度
- [ ] 飞行模式下列表页与答题页仍可访问
- [ ] 兜底单文件版可从 U 盘直接双击打开刷题

## 9. 度量指标

| 指标 | 目标值 | 采集方式 |
|---|---|---|
| 全量刷题通过率 | ≥ 90% | 站点统计页 |
| 单题平均作答时长 | < 20s | 本地埋点 |
| 首屏加载 | < 1.5s（4G） | Lighthouse |
| 离线可用性 | 100% 题目可离线作答 | 手动飞行模式验证 |
| 房间同步延迟 | < 1s 局域网 / < 2s 公网 | 双设备实测 |
