# 04 · 产品设计与交互规范

> 本文档定义站点的信息架构、页面构成、答题交互、即时反馈机制与多人玩法。
> 设计主题：视觉语言取自**荷兰风格派与包豪斯**——红黄蓝三原色点缀 + 规整网格构图，与本课程内容形成呼应。

---

## 1. 用户与场景

### 1.1 用户画像

| 画像 | 特征 | 核心诉求 |
|---|---|---|
| **备考者（主）** | 考前 1–2 天、时间碎片化、时间多花在手机上 | 快速刷完全部题、记住易错点 |
| **结伴复习者** | 2–5 人一起在宿舍/图书馆 | 一起刷、看别人进度互相追、有人陪着不容易放弃 |
| **临时查看者** | 同学发来链接点开看看 | 零门槛打开就能答，不需要注册 |

### 1.2 典型场景

| 场景 | 设备 | 网络 | 关键需求 |
|---|---|---|---|
| S1 躺在床上快速刷题 | 手机 | 良好 | 单手操作、反馈明确、可随时中断续做 |
| S2 图书馆组队复习 | 手机 + 电脑 | 一般 | 房间同步、进度可见、能互相追进度 |
| S3 考前 30 分钟最后冲刺 | 手机 | 可能无网 | 离线可用、只看错题、只看速记卡 |
| S4 课间抽查同学 | 手机 | 良好 | 分享单题链接、快速批改 |

## 4. 答题交互规范

### 4.1 通用规则

| 规则 | 规范 |
|---|---|
| 触控目标 | 所有可点击元素 ≥ 44×44px，选项卡片高度 ≥ 56px |
| 单选 | 点击即提交，**立即**反馈（不设「确认」按钮） |
| 多选 | 点击切换选中态，需点「提交答案」确认（避免误判） |
| 判断 | 两个大按钮「正确 ✓」「错误 ✗」，点击即提交 |
| 填空 | 每个空独立输入框，多空时按 Enter 跳到下一空；最后点「提交」 |
| 键盘 | 选择题禁用弹起键盘；填空题调起对应键盘（数字题 `inputmode="numeric"`） |
| 反馈后 | 显示「下一题」按钮，并支持**左滑下一题 / 右滑上一题**手势 |
| 中断恢复 | 退出时保存当前索引与已作答结果，重进时询问「继续上次 / 重新开始」 |
| 不计时 | 默认**不强制计时**（复习不是考试），仅在抢答模式启用倒计时 |

### 4.2 单题状态机

```
        ┌──────────┐
        │ 未作答    │
        └────┬─────┘
             │ 用户操作
             ▼
     ┌───────────────┐
     │ 已选择/已填写   │  ← 多选、填空可反复修改
     └───────┬───────┘
             │ 提交（单选/判断为点击即提交）
             ▼
     ┌───────────────┐
     │ 已判分・展示反馈 │  ← 锁定选项，不可再改
     └───────┬───────┘
             │ 点「下一题」
             ▼
        下一题 / 结果页
```

### 4.3 填空题的题干渲染

题干按 `stemParts` 渲染，空位是内联输入框：

```
1851 年英国成功举办了第一届世界博览会，展馆运用全玻璃钢结构
建成，称为「[ 水晶宫 ]」，被誉为 20 世纪现代建筑的开山之作。
```

- 空位宽度自适应答案长度（`min 80px`，按 `answer.value[i].length` 估算）
- 提交后：正确 → 输入框变绿底；错误 → 红底 + 下方显示正确答案
- 移动端多空时自动滚动到当前空位

## 5. 即时反馈设计（核心体验）

这是整个产品**最重要的 300 毫秒**。目标：让学生不用思考就知道「对没对、为什么错、要记什么」。

### 5.1 反馈的构成

```
┌─────────────────────────────────────┐
│  ┌───────────────────────────────┐  │
│  │  ✓ 回答正确                    │  │ ← 结果条：绿底白字 / 红底白字
│  └───────────────────────────────┘  │
│                                     │
│  你的答案：B  阿什比                 │ ← 与正确答案并排对比
│  正确答案：B  阿什比                 │
│                                     │
│  ── 解析 ────────────────────────   │
│  英国工艺美术运动金工设计领域代表    │ ← 解析区（无解析时展示知识卡）
│  人物是查尔斯·阿什比。               │
│                                     │
│  相关知识点 ▸  英国「工艺美术」运动   │ ← 反查知识卡，建立知识关联
│                                     │
│         [ 这题答案有问题 ]           │
└─────────────────────────────────────┘
```

### 5.2 反馈时序

| 阶段 | 时长 | 表现 |
|---|---|---|
| T0 用户提交 | 0ms | 立即锁定选项，按钮进入 loading 态（≤50ms，本地判分几乎无感） |
| T1 结果呈现 | 0–120ms | 正确答案的选项卡片边框变绿并轻微放大（`scale 1.0→1.02→1.0`）；错选变红并轻微抖动（`translateX ±4px`，2 次） |
| T2 面板展开 | 120–280ms | 反馈面板从下方滑入（`translateY 16px→0`，`ease-out`） |
| T3 内容就绪 | 280ms | 解析文字淡入（`opacity 0→1`，150ms） |

- **总时长 ≤ 300ms**，不设「等待网络」环节（判分在本地）。
- 尊重 `prefers-reduced-motion`：开启时跳过动效，直接呈现结果。

### 5.3 反馈文案规范

| 情境 | 文案 |
|---|---|
| 答对 | `✓ 回答正确` |
| 答对但模糊匹配命中 | `✓ 判为正确（与你输入不完全一致）` |
| 答错 | `✗ 回答错误` |
| 多选漏选 | `✗ 少选了 N 个` + 列出漏选项 |
| 多选多选 | `✗ 多选了 N 个` + 列出多余项 |
| 填空部分正确 | `△ 3 个空对了 2 个` + 逐空标注 |
| 判断题答错 | `✗ 正确答案是「错」` |
| 无解析 | 自动展示关联知识卡要点（若能匹配到 tags） |

**文案原则**：不说「真可惜」「再想想」这类空话；只给**可执行的信息**（对/错、正确答案是什么、为什么）。

### 5.4 连续答对的轻激励

- 连对 3 / 5 / 10 题时，在结果条右侧出现一个小色块徽记（不弹窗、不打断）；
- 用刻度感而非游戏化喧哗，避免干扰复习节奏。

## 6. 移动端适配规范

### 6.1 断点

| 断点 | 目标 | 布局 |
|---|---|---|
| `< 640px` | 手机竖屏 | 单列，底部 Tab，全宽卡片 |
| `640–1024px` | 平板 / 手机横屏 | 两列，保留底部 Tab |
| `> 1024px` | 桌面 | 左侧固定导航 + 居中内容区（最大宽 960px） |

### 6.2 硬性检查项

- [ ] 375px 宽下无横向滚动条
- [ ] 思考题：长题干 + 4 个长选项在小屏下可通过滚动完整阅读
- [ ] 底部安全区适配（iPhone Home Indicator，`padding-bottom: env(safe-area-inset-bottom)`）
- [ ] 字号不小于 16px（避免 iOS 自动放大）
- [ ] 横屏时可答题（不强制竖屏）
- [ ] 微信内置浏览器实测可用（国内真实入口）

### 6.3 视觉规范

| 项 | 取值 |
|---|---|
| 主题 | 浅色为默认，支持跟随系统切换暗色 |
| 底色 | `#FAFAF8`（暖白，长时间阅读不刺眼） |
| 卡片 | `#FFFFFF` + 1px 边框 `#E8E6E0` + 轻阴影 |
| 主色（品牌） | 包豪斯红 `#D8342B` |
| 强调色 | 风格派蓝 `#1B4C9C`、风格派黄 `#F2B705` |
| 正确 | `#1E8E5A`（绿） |
| 错误 | `#D8342B`（红） |
| 正文文字 | `#1F1F1F` |
| 次要文字 | `#6B6B6B` |
| 标题字体 | `Noto Serif SC` / 系统衬线（呼应历史学科气质） |
| 正文字体 | `system-ui, -apple-system, "PingFang SC", sans-serif` |
| 圆角 | 卡片 12px，按钮 8px，选项卡 10px |
| 间距刻度 | 4 / 8 / 12 / 16 / 24 / 32px |

> 注意：这里的三原色是**装饰性使用**（进度条、色块、徽记），不用于传达对错语义，避免与红=错、绿=对混淆。

## 7. 多人房间玩法

### 7.1 房间概念

| 项 | 设计 |
|---|---|
| 房间码 | 6 位大写字母数字，排除易混的 `O / 0 / I / 1` |
| 加入方式 | 输入房间码，或扫房主分享的二维码（链接 `#/room?c=XXXXXX`） |
| 上限 | 建议 ≤ 10 人（WebRTC 星型拓扑的舒适区） |
| 身份 | 昵称 + 随机头像色块（无需注册） |
| 通道状态 | 房间顶部常驻显示「🟢 实时同步中（WebRTC）」或「🟡 兼容模式（MQTT）」或「🔴 已离线」 |

### 7.2 三种房间模式

#### 模式一：同步刷题（默认）

房主控制进度，所有人做同一题；每人在自己设备上作答，本地判分，互不干扰。

```
┌─────────────────────────────────┐
│  房间 H7K2M9          🟢 实时  │
├─────────────────────────────────┤
│  第 12 / 78 题                  │
│  ┌───────────────────────────┐  │
│  │ 扫码加入 / H7K2M9          │  │ ← 二维码
│  └───────────────────────────┘  │
│                                 │
│  成员          进度     正确率   │
│  ─────────────────────────────  │
│  👑 我         12/78    92%     │ ← 房主标记
│  🟦 小明       12/78    83%     │
│  🟨 阿May      11/78    100%    │
│  🟩 老王        9/78    78%     │
│                                 │
│  [ 下一题（房主可点） ]          │
└─────────────────────────────────┘
```

#### 模式二：抢答 PK

同一题倒计时 20s，先答对者得分（剩余时间越多分越高），答错则本题失去抢答机会。

```
┌─────────────────────────────────┐
│  ⏱ 剩余 14s                     │
│  下列属于“新建筑”运动设计师的是？ │
│                                 │
│  A. 格罗皮乌斯    🟦小明 已选     │
│  B. 密斯·凡·德·洛                 │
│  C. 柯布西耶                     │
│  D. 阿尔托                       │
│                                 │
│  本轮得分：我 30 · 小明 20 · 老王 0│
└─────────────────────────────────┘
```

#### 模式三：接力轮答（P2）

按顺序轮流指定答题人，答对则团队连击 +1，答错连击清零。

### 7.3 同步边界

| 广播 | 不广播 |
|---|---|
| 昵称、头像色 | 题目答案明文 |
| 已答题数、正确数、当前题号 | 个人错题明细 |
| 房主推进题号的指令 | 个人作答内容 |
| 抢答模式下「XX 已抢答」事件 | 抢答者选了什么选项（仅广播是否正确） |

这样设计的原因：公共 MQTT broker 上消息是明文，房间安全性仅依赖房间码。**能少暴露就少暴露。**

### 7.4 异常处理

| 情况 | 表现 |
|---|---|
| 房主断线 | 30s 后提示「房主已离线，已切换为各自独立刷题」，进度不再受房主控制 |
| 成员断线 | 成员列表置灰并保留 2 分钟，重连后恢复 |
| 所有通道均失败 | 明确提示「多人同步不可用，已切换单机模式」，答题功能完全不受影响 |
| 房间码不存在 | 「房间不存在或房主已离开」，提供「自己开一个」按钮 |

## 8. 空状态与异常状态

| 场景 | 表现 |
|---|---|
| 无错题 | 「还没有错题 —— 说明你都答对了」+ 去刷题按钮（不用「空空如也」这类消极文案） |
| 今日无待复习 | 「今日复习已清空，共完成 N 题」+ 可继续加练 |
| 数据加载失败 | 错误卡片 + 「重试」+ 「使用离线数据」双按钮，**绝不白屏** |
| 离线模式 | 顶部常驻细条 `⚠ 离线模式，数据可能不是最新` |
| 判分为模糊命中 | 结果条下方小字提示并给「我答错了」手动纠正入口 |

## 10. 无障碍与包容性

- 所有可交互元素有可见焦点态（`focus-visible` 描边）；
- 结果不只靠颜色区分：正确用 `✓` + 绿色，错误用 `✗` + 红色（色盲可用）；
- 支持键盘完整操作（Tab 切换选项、Enter 提交、方向键切题）；
- 尊重 `prefers-reduced-motion`；
- 语义化标签与 `aria-live="polite"` 播报判分结果，便于读屏。
