# 06 · 部署与运维手册

> 目标：把站点发布到 GitHub Pages，任何人用手机打开链接即可刷题；更新一次不超过 3 分钟。

---

## 1. 部署总览

```
本地 push 到 main
      │
      ▼
GitHub Actions 触发
      ├─ 1. Checkout
      ├─ 2. Setup Node 20 + 缓存 npm
      ├─ 3. npm ci
      ├─ 4. npm run lint
      ├─ 5. npm run test            ← 判分/调度单测，失败即中止
      ├─ 6. npm run data:validate   ← 数据质量校验 V1–V12
      ├─ 7. npm run build           ← 产物到 dist/
      └─ 8. upload-pages-artifact → deploy-pages
                │
                ▼
      https://<用户名>.github.io/<仓库名>/
```

**关键点**：单测与数据校验作为部署门禁。判分逻辑坏了就不许上线，这比上线后发现答案判错要划算得多。

## 2. 首次部署

### 2.1 创建仓库

```bash
# 在项目根目录
git init
git add .
git commit -m "chore: 初始化现代设计史刷题站"
git branch -M main
git remote add origin https://github.com/<用户名>/design-history-quiz.git
git push -u origin main
```

> 仓库设为 **Public**。Private 仓库的 Pages 需要付费方案。

### 2.2 配置 Vite base

GitHub Pages 部署在子路径 `/<仓库名>/`，必须让 Vite 知道：

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import { VitePWA } from 'vite-plugin-pwa';

export default defineConfig(({ mode }) => ({
  // 仓库名为 design-history-quiz 时即为此值；若用 user.github.io 根仓库则设为 '/'
  base: process.env.VITE_BASE ?? '/design-history-quiz/',
  build: { outDir: 'dist', sourcemap: mode !== 'production' },
  plugins: [react(), VitePWA({ /* 见 2.4 */ })],
}));
```

**忘了设 `base` 是最常见的翻车点**：页面能打开但 JS/CSS 全部 404，白屏。

### 2.3 Actions 工作流

`.github/workflows/deploy.yml`：

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:        # 支持手动触发（应急重部署）

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true   # 连续推送时只保留最后一次

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm

      - name: 安装依赖
        run: npm ci

      - name: 代码检查
        run: npm run lint

      - name: 单元测试（判分与调度）
        run: npm run test

      - name: 数据质量校验
        run: |
          python3 -m pip install --quiet --disable-pip-version-check rich || true
          python3 tools/validate_data.py data/

      - name: 构建
        run: npm run build
        env:
          VITE_BASE: /design-history-quiz/

      - uses: actions/configure-pages@v5

      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

### 2.4 启用 Pages

1. 仓库 → **Settings** → **Pages**
2. **Source** 选择 `GitHub Actions`（**不要**选 "Deploy from a branch"）
3. 保存后回到 **Actions** 标签，等待 `Deploy to GitHub Pages` 跑完（首次约 1–2 分钟）
4. 访问 `https://<用户名>.github.io/design-history-quiz/`

### 2.5 PWA 与服务端缓存

GitHub Pages 无法自定义响应头，因此缓存控制靠**文件名 hash**（Vite 默认行为）+ 查询串：

```ts
// 数据请求带版本串，题库更新后立即生效
const url = `${import.meta.env.BASE_URL}data/questions.json?v=${DATA_VERSION}`;
```

| 资源 | 策略 |
|---|---|
| `assets/index-<hash>.js` | 文件名含 hash，可长期缓存 |
| `index.html` | 不加 hash，通过 PWA 的 `navigateFallback` 处理 |
| `data/*.json` | 带 `?v=<dataVersion>` 查询串 |
| Service Worker | 预缓存全部数据文件，离线可用 |

PWA 关键配置：

```ts
VitePWA({
  registerType: 'autoUpdate',
  includeAssets: ['icons/*.png'],
  manifest: {
    name: '现代设计史 · 刷题复习',
    short_name: '设计史刷题',
    start_url: './',
    display: 'standalone',
    theme_color: '#D8342B',
    background_color: '#FAFAF8',
  },
  workbox: {
    globPatterns: ['**/*.{js,css,html,json,svg,png}'],
    // 数据文件优先走缓存，弱网时也能秒开
    runtimeCaching: [{
      urlPattern: /\/data\/.*\.json$/,
      handler: 'StaleWhileRevalidate',
      options: { cacheName: 'dsquiz-data' },
    }],
  },
})
```

> **注意**：`autoUpdate` 模式下用户下次打开才会拿到新版本。题库更新后如果同学说"还是旧的"，让他下拉刷新或关掉标签页重开。

## 3. 日常更新流程

```bash
# 1. 改代码或数据
# 2. 本地自检
npm run lint && npm run test && npm run data:validate && npm run preview
# 3. 提交
git add -A
git commit -m "data: 修正 hw1-q15 答案"
git push
# 4. 等 Actions 跑完（约 1–2 分钟），刷新线上页面
```

### 3.1 只改题库（最常见）

```bash
npm run data:build        # 从 Markdown 重建 questions.json
npm run data:validate     # 必须全通过
# 提升 data/questions.json 里没有的 dataVersion（在 src/core/loader.ts 的常量中）
git commit -am "data: 重建题库并提升数据版本"
git push
```

## 4. 多人同步的运维说明

本站**没有自建服务端**，因此没有服务器要维护。依赖的两个第三方免费服务：

| 服务 | 用途 | 地址 | 失效表现 | 应对 |
|---|---|---|---|---|
| PeerJS 公共信令 | 建立 WebRTC 连接 | `0.peerjs.com` | 建房/加入失败 | 自动降级到 MQTT |
| EMQX 公共 MQTT broker | 兼容模式广播 | `wss://broker.emqx.io:8084/mqtt` | 房间状态不同步 | 提示切单机模式 |

| 风险 | 说明 | 缓解 |
|---|---|---|
| 公共信令被墙或限流 | 宿舍网络偶发 | 三级降级链（见技术文档 5.1），房间页显示当前通道 |
| MQTT 公共主题被干扰 | 别人可能订阅同主题 | 房间码加随机后缀作为主题名，只广播进度不广播答案 |
| 服务长期不可用 | 免费公共服务无 SLA | 单机刷题始终可用，多人只是锦上添花 —— 这是本架构的核心容错设计 |

## 5. 常见问题排障

| 现象 | 原因 | 解决 |
|---|---|---|
| 页面白屏，控制台一堆 404 | `base` 配置与仓库名不匹配 | 检查 `vite.config.ts` 的 `base` 与 Actions 里的 `VITE_BASE` |
| 打开是 404 页面 | Pages Source 选了 "Deploy from a branch" | 改为 `GitHub Actions` |
| 刷新子路由 404 | 用了 BrowserRouter | 改 HashRouter（本项目已用 Hash 路由） |
| 页面还是旧版本 | CDN / Service Worker 缓存 | 硬刷新（Ctrl+Shift+R）；手机端关标签页重开；确认 `dataVersion` 已提升 |
| Actions 失败在 `npm ci` | lock 文件与 package.json 不一致 | 本地跑 `npm install` 后提交新的 lock 文件 |
| Actions 失败在 `data:validate` | 题库数据有结构错误 | 本地跑 `npm run data:validate` 看具体是哪条 V 规则失败 |
| 判分测试失败 | 改动了 `grader`/`normalize` | 本地 `npm run test` 定位，**不允许跳过该测试上线** |
| 房间建不起来 | 信令服务不可达 | 房间页手动切到「兼容模式（MQTT）」 |
| 房间能进但进度不同步 | 消息节流配置过激 | 检查节流阈值（默认 500ms），或检查是否被浏览器节流后台标签 |
| 手机上手感卡顿 | 答题时重算了题目队列 | 检查是否每题都调用了队列生成函数；应在进入练习时一次生成 |
| 填空题判错但答案看起来一样 | 归一化未覆盖该差异 | 在 `normalize` 测试中补用例，加到同义词表或标点表 |
| PWA 无法安装 | 非 HTTPS 或 manifest 缺图标 | Pages 默认 HTTPS；检查 `manifest.icons` 的尺寸与路径 |

## 6. 兜底方案（必须准备）

### 6.1 单文件离线版

D2 考前导出一份自包含 HTML：

```bash
npm run build:standalone
# 产出 dist-standalone/index.html（内联全部 JS/CSS/数据，约 400–600KB）
```

用途：

| 场景 | 用法 |
|---|---|
| Pages 挂了 | 微信/QQ 直接发文件给同学，双击浏览器打开 |
| 考场/宿舍无网 | 存到手机「文件」App，用浏览器打开本地文件 |
| 演示/答辩 | 无需网络，零配置 |

> 单文件版不支持多人同步，其余功能完整。

### 6.2 进度导出

站点「设置」页提供：

- **导出进度**：下载 `dsquiz-progress-<日期>.json`（含错题、盒状态、统计）
- **导入进度**：选择 JSON 文件恢复
- **导出错题清单**：生成 Markdown 文本，可直接贴进笔记或发给同学

换手机、清缓存、换浏览器都不丢复习记录。

## 7. 回滚

```bash
# 方式一：revert 某次提交（推荐）
git revert <commit-sha>
git push            # Actions 自动重新部署，约 2 分钟

# 方式二：Actions 手动重跑历史成功构建
# 仓库 → Actions → 选中历史 run → Re-run all jobs

# 方式三：GH Pages 无版本回退能力，必须靠 Git 历史（因此每次提交都要能构建通过）
```

## 8. 上线检查清单

### 首次部署

- [ ] 仓库为 Public
- [ ] `vite.config.ts` 的 `base` 与仓库名一致
- [ ] Pages Source 设为 `GitHub Actions`
- [ ] Actions 三个门禁（lint / test / data:validate）全部通过
- [ ] 线上地址手机能打开
- [ ] 手机实测：能答题、能看反馈、能进错题本

### 每次更新

- [ ] 本地 `npm run preview` 验证过
- [ ] 数据改动已提升 `dataVersion`
- [ ] 部署后硬刷新确认线上已是新版本
- [ ] 如改了判分逻辑，78 题标准答案回归测试通过

- [ ] 功能已冻结，无未完成分支
- [ ] 全站手工回归（见 `01-开发计划.md` 第 8 节）
- [ ] 单文件兜底版已导出并发送到手机
- [ ] 进度已导出备份
