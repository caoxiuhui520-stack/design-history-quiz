# 03 · 知识库与数据规范

> 本文档定义「知识库存放」：数据资产清单、JSON Schema、判分与归一化算法、导入流水线、数据质量规则与更新流程。

## 2. 文件布局与版本策略

```
data/                          ← 源数据（唯一真源，纳入 Git 版本控制）
├─ questions.json
├─ concepts.json
└─ essays.json

public/data/                   ← 构建产物（由 npm script 复制，不手工编辑）
tools/parse_bank.py            ← 导入流水线（Markdown → JSON）
tools/validate_data.py         ← 数据质量校验（CI 中执行）
```

| 规则 | 说明 |
|---|---|
| 单一真源 | 只改 `data/`，`public/data/` 由脚本生成，禁止手工编辑 |
| 版本号 | 每个文件顶层 `schemaVersion`（语义化版本），字段结构变更必须升版本 |
| 数据版本 | 建议在 `questions.json` 增加 `dataVersion`（如 `2026.09.13-1`），前端页面页脚展示，便于同学确认是否拿到最新题库 |
| 缓存失效 | 前端请求加 `?v=<dataVersion>`，避免 CDN 缓存旧题 |

## 3. Schema 定义

### 3.1 `questions.json`

```jsonc
{
  "schemaVersion": "1.0.0",
  "course": "现代设计史",
  "generatedFrom": [ { "homework": 1, "workId": "54136028", "file": "..." } ],
  "stats": {
    "total": 78,
    "byType": { "single": 33, "multiple": 4, "judge": 18, "blank": 23 },
    "byChapter": { "新艺术运动": 15 }
  },
  "questions": [ /* Question[] */ ]
}
```

#### Question 对象

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 全局唯一，格式 `hw<作业号>-q<两位题号>`，如 `hw3-q12` |
| `type` | `"single" \| "multiple" \| "judge" \| "blank"` | ✅ | 题型，决定渲染组件与判分策略 |
| `chapter` | string | ✅ | 章节归属，用于筛选与统计 |
| `stem` | string | ✅ | 题干纯文本（**不含选项**，选项剥离到 `options`） |
| `options` | `{key,text}[]` | 单选/多选 | 选项，`key` 为 A–E |
| `answer` | Answer | ✅ | 标准答案与容错候选 |
| `explain` | string | | 答案解析，可能为空串 |
| `tags` | string[] | ✅ | 形如 `人物:莫里斯`、`运动:包豪斯`、`作品:红屋` |
| `source` | object | ✅ | 溯源信息 |
| `stemParts` | string[] | 填空 | 按 `[?]` 切分的题干片段，长度 = 空位数 + 1 |
| `blankCount` | number | 填空 | 空位数 = `stemParts.length - 1` |

#### Answer 对象

```jsonc
{
  "value": ["A"],                        // 机器判分用：选项字母数组 / ["T"] / 填空答案数组
  "display": "A",                        // 展示用：给用户看的答案文本
  "accepted": ["A"]                      // 容错候选（判断题为 对/错/√/×/true/false）
}
```

- `single` / `multiple`：`value` 为选项字母数组，按字母升序
- `judge`：`value` 为 `["T"]` 或 `["F"]`
- `blank`：`value` 为按空位顺序排列的答案数组，第 n 项对应第 n 个 `[?]`

#### 完整示例

```jsonc
{
  "id": "hw2-q01",
  "type": "blank",
  "chapter": "包豪斯",
  "stem": "[?]年，德国设计学院包豪斯在[?]成功举办国际构成主义和达达主义研讨大会，促进了新的[?]观念的形成。",
  "options": [],
  "answer": {
    "value": ["1922", "杜塞尔多夫", "国际构成主义"],
    "display": "1922；杜塞尔多夫；国际构成主义",
    "accepted": ["1922", "杜塞尔多夫", "国际构成主义"]
  },
  "explain": "",
  "tags": ["运动:包豪斯", "运动:构成主义"],
  "source": { "homework": 2, "workId": "54136012", "no": 1, "typeName": "填空题" },
  "stemParts": ["", "年，德国设计学院包豪斯在", "成功举办国际构成主义和达达主义研讨大会，促进了新的", "观念的形成。"],
  "blankCount": 3
}
```

### 3.2 `concepts.json`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | `kc-NN` |
| `chapter` | string | 所属章节 |
| `title` | string | 知识主题名 |
| `aliases` | string[] | 别名（用于检索与填空题容错） |
| `definition` | string | 定义句（速记卡的正面） |
| `points` | string[] | 要点列表（速记卡的背面） |
| `slides` | number[] | 回指 PPT 页码，便于溯源核对 |
| `tags` | string[] | 与题库标签体系一致 |
| `examType` | string[] | 该知识点可能的考查形式：`选择`/`填空`/`判断`/`大题`/`名词解释` |

设计意图：`points` 是**可直接背诵的粒度**，每条约 15–40 字；`slides` 保证任何一条要点都能追回课件原文，避免出现无出处的「自编知识点」。

### 3.3 `essays.json`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | `es-NN` |
| `chapter` | string | 所属章节 |
| `title` | string | 大题标题 |
| `prompt` | string | 题目问法 |
| `totalScore` | number | 满分（10 或 12） |
| `keyPoints` | KeyPoint[] | 踩分点列表，`score` 之和必须等于 `totalScore` |
| `reference` | string | 参考答案（完整段落） |
| `slides` | number[] | 依据的课件页码 |
| `relatedQuestions` | string[] | 关联客观题 id，实现「做错客观题 → 反查大题」 |

#### KeyPoint 对象

```jsonc
{
  "text": "缘起于 1850 年代的英国",
  "aliases": ["1850年代", "19世纪50年代", "1850"],
  "score": 2
}
```

`aliases` 是命中判定用的同义表达集合——学生不可能逐字背诵，判定必须接受等价表述。

## 4. 判分与归一化算法

### 4.1 归一化管线 `normalize.ts`

```ts
const PUNCT = /[，。、；：（）()《》""''·・.．,;:!?！？\-—_ 　\t]/g;

export function normalize(s: string): string {
  let out = '';
  for (const ch of s.trim()) {
    const c = ch.codePointAt(0)!;
    if (c === 0x3000) out += ' ';              // 全角空格 → 半角
    else if (c >= 0xff01 && c <= 0xff5e) out += String.fromCharCode(c - 0xfee0); // 全角→半角
    else out += ch;
  }
  return out
    .replace(PUNCT, '')                        // 去标点与空白
    .replace(/[A-Za-z]/g, m => m.toLowerCase()) // 英文小写
    .replace(/[零〇一二两三四五六七八九十百千]+/g, m => cn2num(m) ?? m); // 中文数字→阿拉伯
}
```

**归一化要覆盖的真实差异**（全部来自本套题库）：

| 原始差异 | 例子 | 归一化后 |
|---|---|---|
| 间隔号不同 | `密斯·凡·德·洛` / `密斯・凡・德・洛` | `密斯凡德洛` |
| 全角字母 | `ＡＴ＆Ｔ` / `AT&T` | `atat` |
| 数字写法 | `1922` / `一九二二` | `1922` |
| 首尾空格、多空格 | `" 1922 "` | `1922` |
| 句末标点 | `水晶宫。` / `水晶宫` | `水晶宫` |
| 译名用字差异 | `格罗皮乌斯` / `格罗佩斯` | 同义词表命中 |

### 4.2 同义词表（译名差异）

题库与课件之间存在译名不一致，必须维护显式同义词表：

| 主词 | 可接受别名 |
|---|---|
| 格罗皮乌斯 | 格罗佩斯、格罗披乌斯 |
| 密斯·凡·德·洛 | 密斯·凡·德罗、米斯·凡·德罗、密斯、米斯 |
| 勒·柯布西耶 | 柯布西耶、勒·柯比意、柯布西埃 |
| 里特维德 | 里特维尔德、格利特·里特维德 |
| 威廉·莫里斯 | 莫里斯 |
| 罗伯特·文丘里 | 文丘里 |
| 维也纳分离派 | 分离派 |
| 威尔德 | 亨利·凡·德·维尔德、亨利·凡·德·威尔德 |

### 4.3 各题型判定策略

```ts
export const strategies = {
  single: (ans: string[], key: string[]) => ans.length === 1 && ans[0] === key[0],

  multiple: (ans: string[], key: string[]) =>
    ans.length === key.length && [...ans].sort().join('') === [...key].sort().join(''),

  judge: (ans: string[], key: string[]) => ans[0] === key[0],

  blank: (ans: string[], key: string[]) =>
    ans.length === key.length &&
    ans.every((a, i) => matchBlank(a, key[i])),
};
```

`matchBlank` 采用四级判定：

```
1. exact     归一化后完全相等                    → 通过，置信度 1.0
2. alias     accepted 列表命中 / 同义词表命中     → 通过，置信度 1.0
3. numeric   数字等价（1922 / 一九二二 / 1922年）  → 通过，置信度 1.0
4. fuzzy     编辑距离 / 最长公共子序列             → 见下方阈值
```

**模糊匹配阈值**（防止把错答判对）：

| 答案长度 | 允许编辑距离 | 说明 |
|---|---|---|
| ≤ 2 字 | 0 | 太短，容错等于放宽标准 |
| 3–5 字 | 1 | 允许一个错别字 |
| ≥ 6 字 | 2 | 长答案允许少量差异 |

模糊命中时反馈文案需降级提示：「**判为正确（与你输入不完全一致）**」，把最终判断权交还用户。

### 4.4 大题踩分点评分

```ts
function scoreEssay(essay, userText) {
  const norm = normalize(userText);
  let got = 0;
  const hits = essay.keyPoints.map(kp => {
    const hit = kp.aliases.concat(kp.text).some(a => norm.includes(normalize(a)));
    if (hit) got += kp.score;
    return { kp, hit };
  });
  return { score: got, total: essay.totalScore, hits };
}
```

**明确的产品立场**：自动评分只作**提示**，不作终判。大题的正确用法是：

```
看题 → 自己在纸上写 → 展开参考答案 → 系统高亮命中的踩分点
     → 用户勾选/补勾漏掉的点 → 系统给出建议分数区间
```

界面必须写清「请自行核对，机器判分仅供参考」，避免学生过度信任自动评分。

## 5. 导入流水线

### 5.1 从 Markdown 题库生成 JSON

```bash
python tools/parse_bank.py <题库目录或文件...> data/questions.json
```

脚本行为：

| 步骤 | 处理 |
|---|---|
| 1. 切块 | 按 `### N. （题型）` 正则切分题目块 |
| 2. 提字段 | 提取 `**题目：**`、`**正确答案：**`、`**解析：**` |
| 3. 剥离选项 | 题干在第一个选项行处截断，选项单独解析为 `options[]`（早期版本曾把选项吞进题干，已修复） |
| 4. 解析答案 | 单选取字母、多选取字母集、判断映射 `T/F`、填空按 `1. 2. 3.` 序号切分 |
| 5. 自动打标 | 用「运动 / 人物 / 作品」三张词典对题干与选项做子串匹配 |
| 6. 自动归章 | 按 `CHAPTER_RULES` 优先级规则命中首个匹配章节 |
| 7. 输出 | 统一排序 `(作业号, 题号)` 后写 JSON |

脚本是**幂等**的：同一批 Markdown 多次运行产出完全一致（已验证 `total=78`，`byType` 与手工统计一致）。

### 5.2 从课件生成知识卡

课件为 `.pptx`，用 `tools/extract_pptx.py` 抽取全部文本（本课件 30 页 / 8664 字）：

```bash
python tools/extract_pptx.py "世界现代设计史.pptx" tools/pptx_dump.txt
```

`concepts.json` 与 `essays.json` 的正文内容基于该抽取文本**人工编写**——不自动生成，因为课件文本存在 OCR/输入残留（如「工银美术」「没计师」「好菜坞」等错字），直接机器切分会把错字带进知识库。

> **数据加工原则：机器负责结构化，人负责内容正确性。** 这条边界不可逾越。

## 6. 数据质量校验规则

`tools/validate_data.py` 在 CI 中执行，任一条失败则中断部署：

| # | 校验项 | 规则 |
|---|---|---|
| V1 | JSON 可解析 | 三个文件均能 `json.load` |
| V2 | 题目总数 | `questions.length === stats.total` |
| V3 | 题型统计 | 实际分组计数与 `stats.byType` 一致 |
| V4 | 答案非空 | 每题 `answer.value` 非空数组 |
| V5 | 选择题答案合法性 | 答案字母必须存在于该题 `options` 中 |
| V6 | 填空题位匹配 | `blankCount === answer.value.length` |
| V7 | 判断题取值 | `value[0] ∈ {"T","F"}` |
| V8 | ID 唯一 | `id` 无重复 |
| V9 | 选项无残留 | `stem` 中不含 `A.`/`B.` 等选项标记 |
| V10 | 大题分值自洽 | `sum(keyPoints[].score) === totalScore` |
| V11 | 标签格式 | 所有 tag 匹配 `^(运动|人物|作品|概念):.+$` |
| V12 | 页码合法 | `slides` 中页码 ≤ 课件总页数（30） |

> 当前状态：V1–V12 **全部通过**（`concepts=31, essays=14, questions=78, 大题得分点=99`）。

## 8. 数据更新流程

```
1. 修改 data/*.json（或更新 Markdown 后重跑 parse_bank.py）
2. 运行 python tools/validate_data.py  → 必须全通过
3. 提升 dataVersion（如 2026.09.13-1 → 2026.09.13-2）
4. 提交信息格式：data: 修正 hw1-q15 克莱斯勒大厦设计者
5. push main → Actions 校验 + 构建 + 部署
6. 站点页脚「数据版本」随之变化，确认线上已更新
```

### 8.1 纠错闭环

站点每道题的反馈面板提供「**这题答案有问题**」按钮：

- 点击后记录 `{questionId, userAnswer, timestamp, note}` 到本地；
- 支持一键复制为 Markdown 片段，直接贴给老师或在 GitHub 提 Issue；
- **不自动改数据**——题库唯一真源在 `data/`，必须经人工确认后提交。
